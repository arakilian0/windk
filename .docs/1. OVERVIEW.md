# Windk Architecture Overview

## Summary & Philosophy

The **Windk CLI** architecture implements a **Just-In-Time (JIT) Dynamic Configuration Resolution Engine** designed specifically for high-reliability execution within the Microsoft Windows Command Shell (`cmd.exe`). 

Traditional Batch-based orchestration tools typically pre-parse or bulk-load configuration files (`.cfg`/`.ini`) into environment memory upon startup. In complex CLI environments, this approach quickly exceeds the native **32 KB Command Shell Environment Block limit**, causing buffer overflows, environment pollution, and unstable parameter evaluation.

WINDK resolves these platform constraints by strictly decoupling execution orchestration into components:

1. **Stateless Router (`tool/windk/cli.bat`)**: Operates as a lightweight parameter categorization and dispatch gateway. It maintains zero internal state tables and forwards parameter scope directly to target subcommands.
2. **Atomic Utility Engine (`lib/config_manager.bat`)**: Encapsulates configuration I/O into isolated, stateless execution contexts. It performs line-buffered JIT key resolution (`GET`) and non-destructive atomic mutations (`SET`).
3. **Autonomous Subcommands**: Independent executables hosted under `tool/toolname` that own their respective domain business logic and local argument parsing.
